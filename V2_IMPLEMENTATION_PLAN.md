# Phase V2 Implementation & Experimental Plan: Statistical Parametric Speech Synthesis

## A. CURRENT SYSTEM UNDERSTANDING
The V1 system is a monophone-based statistical parametric speech synthesis (SPSS) pipeline built on LJ Speech.
1. **Text & G2P**: Raw text is normalized (punctuation, acronyms expanded as letters) and mapped to a sequence of 39 ARPAbet phonemes + `SIL` using `g2p_en` and CMUdict.
2. **Alignment**: MFA aligns audio to phonemes. Boundaries are mapped to acoustic frames (`hop_length=256`, `sr=22050`). Each phoneme interval of $N$ frames is divided linearly into 3 left-to-right states.
3. **Training**: Features are 80-D log-Mel spectrograms. `models/train_hmm.py` computes the empirical mean and diagonal variance for 120 states (40 phones $\times$ 3 states) based on hard frame assignments, flooring variance at $10^{-6}$. Frame durations are also averaged per state.
4. **Synthesis**: Given text, states are assigned their mean empirical integer durations (clamped to $\ge 1$). The 80-D mean of each state is simply tiled/repeated across its duration.
5. **Reconstruction**: The resulting piecewise-constant log-Mel trajectory is inverted via 60 iterations of Fast Griffin-Lim.

**Codebase confirmation**:
I have verified the V1 implementation. The trajectory generated by tiling means produces severe discontinuities at state boundaries, resulting in unnatural, step-function spectral transitions.

## B. ROOT-CAUSE ANALYSIS
**1. Trajectory-Generation Limitations (Critical Hypothesis)**
V1 synthesizes by repeating the static state mean. This creates a piecewise-constant spectrogram without temporal continuity constraints. Phase reconstruction (Griffin-Lim) struggles with artificial spectral discontinuities, which we hypothesize contributes significantly to the "robotic" timbre and high WER.

**2. Acoustic Model Limitations (Out of Scope for Initial V2)**
Monophones with single Gaussians lack contextual awareness (co-articulation is ignored). However, evaluating the trajectory discontinuity problem is a mathematically necessary prerequisite before evaluating GMMs or triphones.

**3. Reconstruction Limitations (Reference Diagnostics)**
The oracle Griffin-Lim experiment achieved 5.5% WER, proving that the representation and reconstruction pipeline retains substantial linguistic information. The Oracle is a diagnostic tool for the pipeline's ceiling, NOT an optimization target for model selection.

## C. RESEARCH-BACKED V2 DESIGN: DYNAMIC FEATURES & MLPG
The first V2 experiment isolates the introduction of **Dynamic Features (Delta + Delta-Delta) and Maximum Likelihood Parameter Generation (MLPG)**.

- **Feature Dimensions**: 80-D Static + 80-D Delta + 80-D Delta-Delta = **240-D**.
- **Dynamic Feature Computation & Boundary Handling (Explicit)**:
  - We will use standard 1st-order and 2nd-order polynomial regression windows. 
  - For Delta ($W_1$): $[-0.5, 0, 0.5]$.
  - For Delta-Delta ($W_2$): $[1.0, -2.0, 1.0]$.
  - **Utterance-Wide Computation**: Deltas must be computed over the *entire* utterance before any state segmentation. They will *never* be computed separately inside individual phoneme/state segments.
  - **Boundary Behavior**: We will use strict edge-padding (replicating the first frame $c_0$ for $t < 0$ and the last frame $c_{T-1}$ for $t \ge T$). This identical boundary convention will be strictly implemented in both training feature extraction and the MLPG synthesis matrix $W$.
- **MLPG Optimization**:
  Maximize $P(O | \lambda, Q) \propto \exp(-\frac{1}{2} (W C - \mu)^T U^{-1} (W C - \mu))$
  The optimal static trajectory $C$ solves: $(W^T U^{-1} W) C = W^T U^{-1} \mu$
- **Solver & Sparsity**: For our diagonal covariance assumption, the dimensions decouple. We solve $D=80$ independent sparse, banded linear systems (pentadiagonal) using a banded solver.

## D. TRAINING CHANGES
V2 training (`models/train_hmm_v2.py`) must compute 240-D features:
1. Extract the $T \times 80$ static log-Mel for each training utterance.
2. Apply delta and delta-delta windows over the entire $T \times 80$ sequence using edge-padding at utterance boundaries.
3. Concatenate to form a $T \times 240$ feature matrix.
4. Slice this utterance-wide matrix according to the MFA alignments.
5. Compute empirical means $\mu_{p,s}$ (240-D) and variances $\sigma^2_{p,s}$ (240-D).
6. Duration statistics remain identical to V1.

## E. SYNTHESIS CHANGES
V2 inference (`synthesis/synthesize_v2.py`) will:
1. Predict state sequence and durations.
2. Construct the utterance-length $T \times 240$ mean sequence $\mu$ and variance sequence $\sigma^2$ by tiling state parameters.
3. Form precision sequence: $U^{-1} = 1.0 / \sigma^2$.
4. For each feature dimension $d \in \{1..80\}$:
   - Construct the banded matrix $R = W^T \text{diag}(U_d^{-1}) W$ strictly enforcing edge-padding boundaries.
   - Construct the right-hand side $r = W^T (U_d^{-1} \odot \mu_d)$.
   - Solve $R C_d = r$ for the optimized static trajectory.
5. Pass the continuous $C$ trajectory to Griffin-Lim.

## F. EXPERIMENTAL PLAN & VALIDATION GATES
The experiment is strictly hypothesis-driven to determine if MLPG improves temporal realism and objective metrics compared to frozen V1.

**Gate V2-0: V1 Validation Baseline (Prerequisite)**
- Evaluate the completely frozen V1 model on all **655 utterances** in `data_splits/val.txt`.
- Save results to `outputs/evaluation/v1_validation_results.json`.

**Gate V2-1: Dynamic Feature Extraction Correctness**
- Unit test delta/delta-delta convolutions and edge padding correctness.

**Gate V2-2: V2 Training**
- Train V2 model; verify 240-D statistics (no NaNs, variance flooring).

**Gate V2-3: MLPG Matrix Mathematical Sanity Test**
- Create a small known synthetic static trajectory C.
- Compute its delta and delta-delta features using the exact chosen boundary convention.
- Construct O = W*C.
- Feed the resulting synthetic observation statistics into MLPG.
- Verify that the recovered C_hat matches the known C within numerical tolerance.

**Gate V2-4: V2 Validation Benchmark**
- Synthesize all **655 validation utterances** using V2.
- Compute paired per-utterance evaluation (V1 vs. V2).
- Produce statistical report (mean, median, standard deviation, bootstrap confidence intervals for V2-V1 metric differences).

**Gate V2-5: Diagnostics & Architecture Freeze**
- Analyze the newly implemented trajectory diagnostics (see Section G).
- Determine if excessive oversmoothing occurs (only then would Global Variance be considered).
- Freeze V2 hyperparameters and architecture based strictly on validation improvement over V1.

**Gate V2-6: Final Test Evaluation**
- Evaluate frozen V1 and frozen V2 on the full **655-utterance** `test.txt` split using the same comprehensive pipeline.

## G. TRAJECTORY DIAGNOSTICS & PAIRED EVALUATION
**Per-Utterance Paired Evaluation**:
For every validation/test utterance, we will compute and retain:
- V1 metric, V2 metric, and the paired difference (V2 - V1).
- We will report mean, median, standard deviation, and bootstrap confidence intervals for the differences to statistically validate improvements.

**Trajectory Diagnostics (Not Optimization Targets)**:
To understand MLPG's effect beyond WER/MCD, we will measure:
1. First-order frame-to-frame spectral change magnitude.
2. Second-order trajectory change magnitude.
3. Global Variance of the trajectory.
4. State-boundary discontinuity magnitude (spectral jump at state transitions).

## H. OVERFITTING PREVENTION & DATA ISOLATION
- **Validation**: All model-selection, debugging, tuning, and V1 vs. V2 comparisons will use the **full 655-utterance Validation set** (`val.txt`).
- **Test Isolation**: The Test set (`test.txt`) will remain completely untouched. Test metrics, audio quality, and WER will NOT be used to guide hyperparameter selection, diagnostic tuning, or architecture decisions.
- **Oracle Independence**: The Oracle reconstruction is solely an Oracle reconstruction reference for diagnosing the log-Mel representation and reconstruction pipeline. V2 optimization will compare strictly against frozen V1.

## I. ISOLATION OF INTERVENTION
The first experiment will isolate MLPG ONLY. We will NOT add Global Variance (GV), Gaussian Mixture Models (GMMs), Context-dependent triphones, or alternative vocoders. GV will only be explored subsequently if V2 validation diagnostics reveal empirical evidence of severe oversmoothing.

## J. EXPECTED FAILURE MODES & DIAGNOSTICS
1. **Inconsistent Boundary Handling**: Training deltas and synthesis $W$ matrix mismatches.
   *Diagnostic*: Create a known synthetic static trajectory C, compute its dynamic features to form O = W*C, feed into MLPG, and verify the recovered C_hat matches C within numerical tolerance.
2. **Ill-Conditioned Banded Matrix**: Small variances causing $U^{-1}$ explosion.
   *Diagnostic*: Use numerical stability diagnostics (solver success, finite values, residual norm ||R*C_hat - r||, variance/precision ranges). Strictly enforce variance floors in training.
3. **Excessive Smoothing**: MLPG flattening formants.
   *Diagnostic*: Measure and compare the Global Variance diagnostic metric against V1 and natural audio.
